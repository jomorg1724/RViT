Attention & Recurrence
in the conv-memory belief model

Four mechanisms, four questions. Two attention blocks decide where to read and from which stream; two recurrent mechanisms decide what persists, and at what timescale. This is the math as implemented in kda_conv_memory_model.py.

SECTION 0

The pipeline — one frame's journey

Every timestep, one 100×100 frame flows through four stages. The accumulator ticks every step; the memory block ticks every 3rd step (mem_every=3); the belief is decoded at every step.

Data flow, one timestep

Two clocks, two memories: the accumulator integrates sensory evidence frame-by-frame; H1 holds trial-scale state and is only rewritten on the slow tick. Attention at both blocks is the same operation — a two-stream competition between what's happening now and what's remembered.

SECTION 1

The complete state inventory — everything that survives from one step to the next

Within a trial, the model carries exactly three recurrent states — the tuple (H1, H2, ACC) threaded through step(). All three are zero-initialized at the start of every trial. Everything else (X_t, Z, att, R, the accumulator's readout) is computed fresh each step and thrown away.

Note the asymmetry: ACC holds 32× more numbers than H1 and H2 combined — and the attention maps agree it is where persistence actually lives.
SECTION 2

Token attention — where do I read from, and from which stream?

Each of the 16×16 = 256 spatial positions is a token. Every position emits a query; the keys come from two competing sources — the observation stream and the memory stream — joined under a single softmax, so mass spent on the past is mass not spent on the present.

The attention matrix A — 256 queries × 512 keys

# tokens: q, k_x, k_h ∈ R^256×C (16×16 map flattened) S_x = q k_x⊤√C S_h = q k_h⊤√C A = softmax( [ S_x ‖ S_h ] ) ∈ R^256×512 att = A_x V_x + A_h V_h # joint softmax ⇒ per-query stream mass sums to 1: # Σ A_x + Σ A_h = 1 (this is the "gate" we plot)

After attention: per-token FFN, concat residual [input ‖ att], SE channel reweighting, 1×1 projection back to C channels. Scores are computed in fp32 — 256-token logits overflow fp16.

The retired pixel-gate variant replaced QKᵀ with a per-pixel scalar inner product + 2-way softmax — a local mixing dial with no spatial routing. Token attention is what actually moves information across positions, which is why the raw 256×256 A (column-summed back onto the scene) is the right object to inspect.

SECTION 3

KDA visual accumulator — what do I remember, and how surprised am I?

The fast integrator. Each pixel carries a small matrix state S (per head, d_k×d_v) that learns key→value associations online by a delta rule: it writes only the prediction error, gated by learned decay and write strength.

Delta-rule write cycle

# from [X_t ‖ H1], per head (h=4, d_k=d_v=32): k = l2norm(W_k·) q = l2norm(W_q·) v = W_v· a_t = σ(W_a·) # per-head-channel decay b_t = σ(W_b·) # write strength # delta rule — write only the prediction error: v̂ = (a_t⊙S)⊤ k # state's current guess err = v − v̂ # surprise S ← a_t⊙S + b_t·k·err⊤ o = RMSNorm(S⊤q) ⊙ σ(W_g·) # gated readout

The readout o is concatenated with X_t to form the vision block's input — attention sees raw now and integrated recent past side by side. The accumulator runs in fp32 regardless of autocast; it is the precision-sensitive recurrence. The surprise map ‖v − v̂‖ is one of our diagnostics — it lights up at the change frame.

SECTION 4

Conv-recurrent memory — what persists across the whole trial?

H1 is the slow, persistent state — the thing that should carry task-relevant content across all 7 steps. H2 is the raw ephemeral read of whatever the memory block just attended to. Updates land only on the slow tick (mem_every=3).

# memory block: Q from H1, keys/values from [Z ‖ H1] att = A_z V_z + A_h1 V_h1 (token attention, §1) H1′ = proj( SE( [H1 ‖ att] ) ) + N(0, σ²) σ=0.05 H2′ = att # raw read, no norm # noise lands ONLY on H1's output, after SE-proj. # H2 and the accumulator stay clean.

The injected noise is a robustness contract: whatever H1 stores must survive perturbation, because the same state is queried by both attention blocks on later steps.

Note what H1 is not: it is not rewritten every step, and (as the maps showed) it is barely re-read — the heavy lifting of persistence is done by the KDA accumulator's matrix state, while H1 behaves more like a slow scratchpad written from the cued observation.

SECTION 6

What the attention maps showed — column-sums of raw A, back on the scene

Each raw A is 256×256 per stream. Column-summing over queries and dividing by 256 projects attention back onto the 16×16 stimulus grid — "how much attention does each scene position receive." Stylized from the measured maps (cue top-left, 100% valid):

A_X · vision, input keys

Sharp focal hotspot at the cue cell, peaking t=3 (~30× uniform). Silent after the change frame — the model stops reading raw input late.

A_H · vision, memory keys

No spatial structure; a broad sheet that saturates at t=5–6. Which queries read memory is selective — what they read is uniform.

A_Z · memory, obs keys

Cue-locked vertical stripes in raw A → focal hotspot in projection. In the invalid condition the hotspot stays at the cue — the 55° change draws nothing.

A_H1 · memory, persistent keys

Bright uniform sheet at t=0, then exactly zero. The persistent state is written but never re-read — persistence lives in the KDA accumulator.

No attention map, in either block, localizes the change — change is carried in state content (88% linear probe on R), not in attention routing.
