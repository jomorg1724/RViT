# Run and artifact registry

This directory contains a deterministic inventory of the workspace's approved metrics-backed training runs.

## Files

- `run_manifest.schema.json` — JSON Schema for each line of the run registry.
- `projects.json` — the producer-project catalog generated by the builder.
- `artifacts.jsonl` — one compact JSON object per discovered run, sorted by stable `run_id`.

The governing policy is [`../_conventions/ARTIFACT_REGISTRY.md`](../_conventions/ARTIFACT_REGISTRY.md).

## Rebuild

Run from `research_db/`:

```bash
../.venv/bin/python tools/build_run_registry.py
```

The command reads only approved artifact roots and refuses to write if discovery differs from the expected 44 candidates. Source-tree hashes are included by default using the deterministic, symlink-safe producer-source allowlist documented in the governing convention; generated outputs, result trees, tests/caches, logs, checkpoints, PDFs, bytecode, and Finder metadata do not affect them. Checkpoint paths are always included. A normal rebuild preserves existing non-null checkpoint hashes for exact run/path pairs.

To stream SHA-256 over checkpoint bytes without loading tensors:

```bash
../.venv/bin/python tools/build_run_registry.py --hash-checkpoints
```

This can be costly because every checkpoint byte must be read. The builder never calls `torch.load` or unpickles checkpoints.

To explicitly discard previously recorded checkpoint hashes:

```bash
../.venv/bin/python tools/build_run_registry.py --drop-checkpoint-hashes
```

The recompute and drop modes are mutually exclusive. Generated files are staged and audited before atomic replacement; a failed coupled replacement rolls back to the prior canonical bytes.

## Audit

```bash
../.venv/bin/python tools/audit_runs.py
../.venv/bin/python tools/audit_runs.py --strict-active
```

The normal audit treats unknown provenance on historical/non-active runs as warnings. `--strict-active` promotes unknown provenance on `status: active` entries to errors. Both modes always reject missing required fields, invalid schema values, duplicate run IDs, and missing or unsafe artifact paths.

Warnings preserve uncertainty; they are not permission to invent missing commands, seeds, timestamps, or devices.

## Interpretation limits

- `logged_phase_complete` means the planned metrics-row budget is present. It does not mean convergence or task success.
- `partial` with `completion_reason: unknown` means the artifacts do not establish why logging stopped.
- Values inferred from directory names are marked in `config` and may carry caveats.
- Registry generation must not alter source metrics, logs, analyses, or checkpoints.
